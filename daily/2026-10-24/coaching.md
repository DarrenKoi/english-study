오늘 배치에는 내가 직접 쓴 한국어 문장이 없다(질문 속 탭 이름 `장비 현황, Recipe 검색, H/W 관리` 뿐). 그래서 어시스턴트의 한국어 보고에서 옮겨 볼 만한 문장을 골랐다.

### 카드 1 — 같은 뿌리의 실수   (고급 한글 · 번역)
- 한글 원문: "`Don't ask to me` 는 10-02 까지 다섯 번 나온 `ask for the help to codex` 와 뿌리가 같습니다."   (출처: transcript:[assistant] english-study c949b1b2)
- 자연스러운 영어: `Don't ask to me` comes from the same root as `ask for the help to codex`, which showed up five times through 10-02.
- 번역 포인트: "뿌리가 같다"는 `comes from the same root as` 또는 `stems from the same habit as` 로 직역해도 통한다. "다섯 번 나온"은 관계절 `which showed up five times` 로 뒤에 둔다. 한국어처럼 명사 앞에 길게 붙이면 영어는 무거워진다. "~까지"는 기간 끝을 포함하는 `through` 가 정확하고 `until` 도 된다.

### 카드 2 — 뺀 이유를 밝히기   (고급 한글 · 번역)
- 한글 원문: "긴 한국어 요청은 Codex 가 Herdr 창으로 보낸 글이라 뺐습니다."   (출처: transcript:[assistant] english-study c949b1b2)
- 자연스러운 영어: I left out the long Korean requests because Codex sent them through the Herdr pane, not you.
- 번역 포인트: "~라 뺐다"의 이유 연결은 `because` 로 풀고 주절(`I left out`)을 앞에 둔다. 영어 보고는 결정을 먼저 말한다. "보낸 글"은 명사구로 옮기기보다 `Codex sent them` 처럼 주어·동사를 살리면 누가 했는지 또렷해진다. `not you` 를 덧붙이면 원문에 숨은 "직접 쓰신 게 아니라서"까지 드러난다.

### 카드 3 — 짝으로 구분하기   (고급 한글 · 번역)
- 한글 원문: "받아 적기는 `write down`, 정리해서 글로 만들기는 `write up` 입니다."   (출처: transcript:[assistant] english-study c949b1b2)
- 자연스러운 영어: Use `write down` for noting something as you hear it, and `write up` for turning it into a proper document.
- 번역 포인트: 한국어의 "A는 X, B는 Y입니다" 대구는 영어에서 `Use X for A, and Y for B` 로 옮기면 지침처럼 읽힌다. "정리해서 글로 만들기"는 `turning it into a proper document` 처럼 동명사 + 결과 명사로 압축한다. 짧게 `X is for A; Y is for B.` 도 자연스럽다.

### 카드 4 — 어느 폴더에 둘지 묻기
- 내가 쓴 영어: "If we need to describe the features from each top nav, where should we put them in one of docs/ folders? Like 장비 현황, Recipe 검색, H/W 관리, 스큐보아 ..."   (출처: transcript:[user] skewnono_v3_nuxt 3df93f7f)
- 정정: `in one of docs/ folders` → `in one of the docs/ folders`. `one of` 뒤에는 특정 집합을 가리키는 한정사(`the`·소유격)가 와야 한다. `Like …` 단독 조각은 글에서는 `e.g., …` 나 `such as …` 로 문장에 붙인다.
- 더 나은 표현: If we want to document what each top-nav tab does (e.g., 장비 현황, Recipe 검색, H/W 관리, 스큐보아), which folder under `docs/` should that go in?
- 왜: `describe the features from each top nav` 는 "nav 에서 나온 기능"처럼 읽힌다. 탭 단위로 설명하려는 의도면 `what each top-nav tab does` 가 정확하다. "어느 폴더?"를 묻는 거라 `where should we put them in one of …` 보다 `which folder … should that go in?` 이 질문의 초점을 바로 세운다. 조건도 `need to` 보다 `want to` 가 자연스럽다(꼭 해야 하는 일이 아니라 하려는 일).
