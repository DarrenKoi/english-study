## 영어 다듬기

### 카드 1 — 할 일 목록 요청
- 내가 쓴 영어: "list up that I have to do now." (같은 세션에서 "list up what py files I should run for test" 도)   (출처: transcript:-Users-daeyoung-Codes-auto-recipe-creator)
- 정정: `list up` 은 영어에 없는 콩글리시다 — `list` 만으로 "열거하다"가 된다(`up` 을 붙이면 `line up`/`sum up` 처럼 다른 뜻을 부른다). 그리고 `list up that I have to do` 는 `that` 뒤에 명사가 없어 문장이 성립하지 않는다. 관계대명사 `what` 이 "~하는 것"을 통째로 목적어로 만들어 준다: `List what I have to do now.` 둘째 문장의 `for test` 도 `for testing` 이나 `to test` 로 고쳐야 한다 — 셀 수 있는 명사 `test` 는 관사 없이 홀로 못 선다.
- 더 나은 표현: Can you lay out what's on my plate right now? / Which test scripts should I be running?
- 왜: `lay out` 은 흩어진 항목을 정리해 펼쳐 보인다는 뜻이라 단순 나열보다 요청 의도에 가깝다. `what's on my plate` 는 "지금 내가 떠안고 있는 일"을 뜻하는 표준 회화 관용구로, 동료에게 쓰기 딱 좋은 격식이다. 두 번째 문장은 `list` 를 아예 버리고 `Which ... should I ~?` 의문문으로 바꾸면 대상이 스크립트임이 문장 첫머리에서 드러난다.

### 카드 2 — 안전 여부 확인
- 내가 쓴 영어: "what py files to run first? is this dry-run ? not actually click right?"   (출처: transcript:-Users-daeyoung-Codes-auto-recipe-creator)
- 정정: `is this dry-run` → `is this a dry run` — `dry run` 은 셀 수 있는 명사라 관사가 필요하고, 명사로 쓸 때는 하이픈 없이 두 단어다(`a dry-run mode` 처럼 형용사로 쓸 때만 하이픈). `not actually click right?` 은 주어와 조동사가 빠져 문장이 아니다 — `it doesn't actually click, right?`
- 더 나은 표현: Which scripts should I run first? Is this a dry run — nothing actually gets clicked, right?
- 왜: 셋 이상이면 `what`, 정해진 후보 안에서 고르면 `which` 다. 여기서는 저장소 안의 스크립트 중 고르는 것이라 `which` 가 맞다. 확인 질문은 `nothing actually gets clicked, right?` 처럼 **부정 주어 + 수동태**로 만들면 "아무것도 안 눌린다"는 게 한 번에 걸려, `not actually click` 같은 조각을 쓰지 않아도 된다. 대시로 두 질문을 이으면 되묻는 말투가 자연스럽다.

### 카드 3 — 공지 배너 문구 요청
- 내가 쓴 영어: "add the comment in the announcement since it is released recently, there might be some bugs to be fixed. if you find any, let me know in person."   (출처: transcript:-Users-daeyoung-Codes-skewnono-v3-nuxt/c9f0075c)
- 정정: 세 군데다. ① `add the comment in the announcement` → `add a note to the announcement` — 처음 언급하는 것이므로 `the` 가 아니라 `a` 이고, 무언가를 문서에 **추가**할 때 전치사는 `in` 이 아니라 `to` 다. ② `since it is released recently` → `since it was released recently` 또는 `since it's only just been released` — `recently` 는 완료된 과거 사건에 붙으므로 단순현재와 짝지을 수 없다. ③ `there might be some bugs to be fixed. if you find any` 앞이 쉼표로 이어져 comma splice 가 났다 — 마침표나 세미콜론으로 끊어야 한다.
- 더 나은 표현: Add a notice to the announcement: since the service has only just been released, there may still be rough edges. If you run into any, please reach out to me directly.
- 왜: `let me know in person` 은 "직접 얼굴 보고"라는 **대면**을 뜻해서, 여기서 의도한 "저에게 직접 연락 주세요"와 다르다. 그 뜻은 `reach out to me directly` 다. `bugs to be fixed` 는 이미 고칠 것이 확정된 목록처럼 들리므로, 공지문에서는 `rough edges`(아직 다듬어지지 않은 부분)가 겸손하고 표준적이다. `find bugs` 보다 `run into` 가 "쓰다가 마주친다"는 사용자 시점을 담는다.

### 카드 4 — 기능 추가 요청

### 카드 5 — 정리 대상 확인 요청
- 내가 쓴 영어: "check the worktree that needs to be handled"   (출처: transcript:-Users-daeyoung-Codes-skewnono-v3-nuxt/2ca1e865)

- 더 나은 표현: Check whether any worktrees still need cleaning up.
- 왜: `whether` 절이 "있는지 없는지"라는 **미확정**을 그대로 담아, 결과가 "없음"이어도 요청이 성립한다. `any` 는 의문·조건절에서 개수를 열어 두는 한정사다. `handle` 은 뜻이 넓어 무엇을 하라는 건지 모호하니, 워크트리 맥락에서는 `clean up`(정리·철거)이 정확하다. `still` 이 "지난번 작업 이후에도 남아 있는지"를 한 단어로 붙인다.

- 왜: `you did a good job` 은 문법은 맞지만 윗사람이 아랫사람을 평가하는 어감이 있어 동료 사이에서는 약간 어색하다. 칭찬의 초점을 사람에서 **결과물**로 옮기면(`that came out clean`) 훨씬 자연스럽고, 무엇이 좋았는지도 함께 전달된다. `what I was after` 는 "내가 원하던 바로 그것"을 뜻하는 회화 관용구로, 요구사항이 정확히 맞았을 때 쓴다.
