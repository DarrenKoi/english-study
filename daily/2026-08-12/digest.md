# 2026-08-12 — 오늘의 표현

- **a band-aid** — 원인은 그대로 둔 채 증상만 덮는 처치. 대안을 깎아내릴 때 가장 짧게 쓰는 한 마디다.
- **the binding constraint** — 여러 제약 중 실제로 결정을 좌우하는 하나. "GPU 는 남는데 호스트 RAM 이 문제다"를 한 구로 끝낸다.
- **a bug factory** — 결함 하나가 아니라 결함이 계속 생산되는 구조. 가정법과 붙어 기각한 설계를 설명한다.
- **the tempting fix** — 누구나 먼저 떠올릴 해법. 먼저 세워 두고 왜 안 골랐는지 밝히면 리뷰 왕복이 한 번 줄어든다.
- **X is the contract, not an oversight** — 어설퍼 보이는 코드가 사실은 지켜야 할 약속이다. 정리하는 사람이 무심코 지우는 사고를 막는다.
- **silently degrade into a guess** — 값이 빠지면 에러 대신 그럴듯한 추측으로 주저앉는다. `silently` 가 위험의 절반을 맡는다.
- **a latent trap, not a current break** — 지금 장애는 아니지만 다음 사람이 밟을 함정. 긴급도와 중요도를 한 줄에 나눈다.

### 오늘의 정독

superpowers brainstorming 스킬 문서의 "작게 나눠라" 단락 — 관계절 하나에 동사 셋을 병렬로 물리고, 서술을 이어 가다 `Can someone …? Can you …?` 두 질문으로 리듬을 바꾼 뒤 `If not, the boundaries need work.` 다섯 단어로 받아 낸다. [reading.md](reading.md) 에 EPIPE 빌드 오진(에러 코드를 프로세스의 1인칭 대사로 번역한 대목)과 variant 기억 설계(가정법 과거완료로 기각한 설계를 말하는 대목) 단락을 더 실었다.

### 오늘의 코칭

오늘 배치는 대화가 전부 영어라 한글→영어 카드는 없다. 영어 다듬기 14장 중:

- `due to there is an icon …` → `because there's an icon …` — `due to` 뒤에는 명사구만 온다. 절을 이으려면 `because`.
- `have we set well?` → `Is that wired up correctly?` — `set` 은 홀로 "설정하다"를 못 맡는다. `set up` · `configure` · `wire up` 으로 구동사를 완성해야 한다.
- `make it remembered the location` → `make it remember which one I picked` — 사역동사 `make` 뒤에는 원형부정사가 온다.
- `oh now it builds done.` → `Oh — it builds fine now.` — `build` 는 여기서 자동사라 뒤에 `done` 이 못 붙는다.
