# 2026-09-24 — 오늘의 표현

- **Short answer: not for X.** — "이거 쓸 수 있어?"에 결론부터. `not for` 로 범위를 좁혀 전면 거절이 아님을 알린다. 뒤에 `One idea from it is worth borrowing, though.` 를 붙이면 균형이 잡힌다.
- **leave it out until someone asks for it** — 있으면 좋은 기능을 실제 요구가 올 때까지 빼 두자는 YAGNI 한 줄. `It's a nice-to-have, so …` 와 짝.
- **Don't build it until X shows the gap.** — 부족할지 모르는 기능은 실제 결과로 빈틈이 드러난 뒤에 만든다. 조건절 `If the first rollout shows …, the fix is …` 와 함께 쓴다.
- **read X as proof that …** — 약한 신호를 증거로 오해하는 위험을 짚을 때. `If reviewers start reading similar_name as proof …`.
- **This changes the answer.** — 새 사실 때문에 앞선 권고를 뒤집는다. "내가 틀렸다" 대신 사실을 주어로 세운다.
- **What this costs:** — 변경 보고에서 대가를 소제목으로 세운다. `What changed:` 다음에 오면 보고가 균형을 찾는다.
- **One thing works differently from what I first described** — 계획과 결과가 다른 점을 스스로 먼저 밝히는 완료 보고의 틀.

### 오늘의 정독
graphify 대신 기존 파이프라인을 권하는 단락. 시제를 `will`(예정)·현재(규칙)·`would`(아직 없는 도구)로 가르고 `Scripts only get sampled, not fully covered, but …` 로 한계를 먼저 인정한 뒤 뒤집는다. 태그 차이를 짚는 단락과 "계획과 달라진 점·대가"를 밝히는 완료 보고는 `reading.md` 에 있다.

### 오늘의 코칭
- 한글→영어: "AutoRAG repo를 발견했어 … 활용 가능한 건지 검토해줘" → `I came across … Could you check whether it would be useful for what we're building?` 우연히 본 건 `found` 가 아니라 `came across`. / "충분히 안정적인거지?" → `Is this stable enough, given that …?` `enough` 는 형용사 뒤에 온다.
- 영어 다듬기: `is it worth of using graphify` → `graphify is worth using`. `worth` 뒤엔 `of` 없이 동명사가 오고 간접 의문문은 평서 어순. / `I just want you to tell what failed` → `just tell me what failed`. `tell` 에는 듣는 사람이 필요하다. 카드 39장은 `coaching.md`.
